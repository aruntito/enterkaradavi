# Contributing to KARADAVI

KARADAVI is a research-oriented project. Contributions should improve the clarity, rigor, reproducibility, or usefulness of the public work.

## Good contributions

- Architecture proposals
- Specification improvements
- Research notes and experiments
- Schema design
- Reference examples
- Documentation corrections
- Reproducible investigations

## Before opening a change

1. Read the relevant material in `docs/`, `specs/`, and `research/`.
2. Keep claims precise and distinguish evidence from interpretation.
3. Do not include private implementation details from the internal KARADAVI repository.
4. Do not include credentials, private data, internal endpoints, or confidential operational information.

## Research standard

When proposing a new concept, explain:

- the problem being addressed;
- the assumptions being made;
- the proposed model or mechanism;
- what evidence supports it;
- known limitations or uncertainty; and
- how the idea could be tested.

## Pull requests

Keep pull requests focused. A good pull request should explain what changed, why it changed, and how the change can be evaluated.

KARADAVI is experimental, so disagreement and iteration are expected. Prefer clear technical reasoning over consensus by default.
