# KARADAVI Roadmap

KARADAVI is being developed as an open knowledge platform and a continuously evolving knowledge institution.

The project has two connected surfaces:

- **Product:** the public knowledge experience and its private production implementation.
- **Public research:** this repository's open conceptual models, specifications, schemas, experiments and documentation.

The public research layer does not mirror or publish the private product implementation.

## North star

Build an extensible, entity-centered, knowledge-graph-first institution that can help people explore meaningful knowledge across the world.

The ten trails—People, Companies, Technology, Science, Space, Concepts, History, Places, Nature & Earth, and Society & Culture—are initial discovery surfaces. They are not a closed ontology or a limit on future knowledge coverage.

The north star is not a launch checklist. The initial release should prove a reliable golden knowledge path before attempting mass population or universal coverage.

## Product completion priorities

### 1. Canonical knowledge path

- [ ] Verify canonical entity identity and alias handling end to end
- [ ] Complete meaningful entity relationship creation and traversal
- [ ] Strengthen claim, evidence and provenance lifecycle semantics
- [ ] Preserve source conflicts, uncertainty and temporal context
- [ ] Ensure published entity pages expose useful context and connections

### 2. Editorial institution

- [ ] Complete deep and standard manual research workflows
- [ ] Mature the AI Editorial Studio for research, extraction and drafting
- [ ] Enforce explicit human approval for every publication and update
- [ ] Preserve editorial decisions and revisions in the knowledge history
- [ ] Improve review, rejection, revision and evidence-request workflows

### 3. Discovery and continuous stewardship

- [ ] Develop source discovery and source validation
- [ ] Improve extraction, normalization and entity resolution
- [ ] Reconcile new source material against existing entities and claims
- [ ] Detect potential conflicts, missing context and stale knowledge
- [ ] Develop autonomous Discover & Update workflows that create reviewable proposals
- [ ] Schedule reconciliation without granting automation publication authority

### 4. Administration, security and operations

- [ ] Complete the dedicated admin surface and access controls
- [ ] Harden roles, audit logs and destructive-action safeguards
- [ ] Complete production hardening, monitoring and editorial QA
- [ ] Keep credentials, private data and internal operational details out of the public repository

### 5. Public discovery and machine readability

- [ ] Complete public entity and knowledge-trail experiences
- [ ] Improve structured metadata and machine-readable representations
- [ ] Complete sitemap, robots directives and llms.txt
- [ ] Mature automated metadata and scheduled consistency checks
- [ ] Improve accessibility, performance and PWA experience

## Permanent editorial invariant

> **AI never publishes.**

AI can discover, research, extract, normalize, compare, draft and propose updates. Only an explicit human editorial decision can approve publication. This applies equally to new entities, corrections, relationship changes and autonomous update workflows.

## Public research roadmap

The public specifications are experimental. Their maturity is earned through tests, counterexamples, documented limitations and interoperability—not by assigning a version number.

### v0.1 — Foundation

- [x] Public architecture and research model
- [x] Public/private boundary
- [x] Entity-state, claim, relation, evidence, provenance, authority and trust schemas
- [x] Reference examples and automated validation
- [x] Contribution and security guidance

### v0.2 — Research depth

- [ ] Define stable terminology and identifier requirements
- [ ] Specify claim lifecycle and conflict semantics
- [ ] Model provenance chains and transformation events
- [ ] Define contextual authority relationships
- [ ] Study uncertainty propagation
- [ ] Establish entity-resolution evaluation cases
- [ ] Define relation semantics and inverse relationship rules
- [ ] Research revision history and editorial approval events
- [ ] Align public primitives with lessons from the product without exposing private implementation

### v0.3 — Reproducible experiments

- [ ] Synthetic benchmark for conflicting claims
- [ ] Authority-context evaluation set
- [ ] Uncertainty propagation experiments
- [ ] Entity-resolution stress cases
- [ ] Claim lifecycle and revision-history benchmark
- [ ] Source reconciliation and stale-knowledge experiments
- [ ] Document failure modes and negative results

### v0.4 — Interoperability

- [ ] Schema versioning policy
- [ ] Compatibility rules
- [ ] Machine-to-machine exchange examples
- [ ] Reference implementation boundaries
- [ ] Interoperability review

### v1.0 — Only when earned

A specification should not be called stable because it is convenient. v1.0 requires evidence that terminology, schemas, semantics and compatibility rules survive real experiments and adversarial cases.

## Long-term direction

The long-term ambition is a continuously maintained knowledge institution that can expand across domains, connect entities and explanations, preserve evidence and provenance, and help readers and machines navigate knowledge without hiding uncertainty.

This is an architectural direction, not a promise of universal coverage or fully autonomous operation.

> Research maturity is earned through evidence, not activity count.
