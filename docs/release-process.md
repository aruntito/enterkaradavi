# Release Process

KARADAVI does not use releases to simulate activity. A release should mark a meaningful public research milestone.

## Before a release

- schemas validate;
- examples validate;
- research claims are clearly labeled;
- breaking changes are documented;
- public/private boundary has been checked;
- changelog is updated;
- roadmap reflects the actual state of the project.

## Release levels

### Research snapshot

A point-in-time collection of experimental research and schemas.

### Candidate

A public model that has survived documented experiments and is being evaluated for compatibility.

### Stable

A model with defined semantics, compatibility expectations, migration guidance, and documented limitations.

Avoid calling an artifact stable simply because it has a version number.
