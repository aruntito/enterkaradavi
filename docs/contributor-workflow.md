# Contributor Workflow

KARADAVI uses a research-first contribution model.

```text
Question
   ↓
Issue / hypothesis
   ↓
Branch
   ↓
Experiment or specification change
   ↓
Validation
   ↓
Pull request
   ↓
Review
   ↓
Merge
```

## Branch naming

Prefer focused names such as:

- `research/<topic>`
- `spec/<topic>`
- `docs/<topic>`
- `experiment/<topic>`
- `fix/<topic>`

## Pull requests

A pull request should explain the problem, the proposed change, the evidence or rationale, and any unresolved questions.

## Main branch

`main` represents the current public surface. Changes should remain reviewable and should not bypass validation simply to increase activity.
